The Problem

Manual GTM does not scale

Sales and GTM teams at early-stage startups waste hours manually researching companies, finding founder emails, and writing cold outreach. Work that repeats every single week.

Each step is slow, inconsistent, and completely automatable. I built a system to do all of it end to end, without a human in the loop.

10 YC companies researched
5 Cold emails sent
10/10 Deliverability score
5 Automated workflows
What I Built

Five workflows. One pipeline.

Every workflow reads from or writes to one Google Sheet. Research, outreach, replies, follow-ups, and scores all in one place. No manual hand-offs.

01

GTM Research Agent

Takes a company name via webhook. Sends it to Groq AI (Llama 3.1 8B). Returns structured research: what they do, who the customer is, their pain point, a trigger event, and a personalized outreach angle. Appends everything to Google Sheets automatically.

Webhook Groq AI Sheets
02

Outreach Sender

Reads rows where status is "Not Sent". Sends a personalized cold email via Gmail using the research data. Updates status to "Sent" and logs the timestamp. Rate-limited to 5 emails per day to protect deliverability.

Sheets Gmail Rate Limiting
03

Reply Tracker

Checks inbox daily for replies from target founders. If a reply comes in, updates reply_status to "Replied" automatically. Runs every morning at 9am via schedule trigger.

Schedule Gmail Sheets
04

Follow-up Sequence

If no reply after 3 days, automatically sends a personalized follow-up using the original outreach angle. Updates status to "Follow-up Sent" so it never fires twice on the same lead.

Schedule Sheets Gmail
05

Lead Scorer

Sends each company's research data to Groq AI and gets back a score (1 to 10) and reasoning. Writes score and score_reason back to the sheet. Run manually to reprioritize outreach at any time.

Sheets Groq AI

The Hard Part

Prompt engineering in production

The biggest bug: Groq kept returning nested JSON objects in the who field instead of plain strings. My parser was breaking on every run.

// The fix: one line added to Groq API request body
"response_format": { "type": "json_object" }

// Forces Groq to return valid JSON every time.
// Combined with field-level instructions and few-shot
// examples in the prompt, the parser has not broken since.

Production-ready means it doesn't break on the 47th run. That took longer to get right than the entire workflow setup.

What I Learned

Automation forces systems thinking

The hardest part was not the automation. It was data quality. Groq would hallucinate nested objects, return wrong companies, or generate generic outreach angles that would not survive contact with a real inbox.

Every bug taught me something about prompt engineering, data validation, and what production-ready actually means when real emails go to real founders.

Automation does not just save time. It forces you to think in systems, and systems expose every assumption you did not know you were making.
